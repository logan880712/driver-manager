# 나의 대리일지

휴대폰에서 하루 근무일지를 쓰고 월 순수익 목표를 관리하는 설치 가능한 웹 앱(PWA)입니다.

## 기능

- 하루 일지: 근무 시작 날짜·시간, 귀가 날짜·시간, 운행 건수, 수수료 차감 후 수익, 팁, 교통비, 기타 지출, 피로도, 메모
- 운행 사진 첨부: JPEG/PNG/WebP 최대 5장, 장당 5MB. 사진에서 금액을 자동 인식하지는 않습니다.
- 순수익 = 수수료 차감 후 운행 수익 + 팁 − 교통비 − 기타 지출
- 월 목표 기본값 250만 원, 화·수 짧은 근무 목표 기본값 10만 원, 목·금 집중 근무 계획
- 기본 근무요일 화·수·목·금, 휴무 날짜·추가 근무 날짜 설정
- 군포역 근처 새벽 3시 전 귀가 기준, 피로도에 따른 안내
- 일지 수정·삭제, 사진을 포함한 JSON 백업·복원, 오프라인 실행, 홈 화면 설치

## 로컬 실행

별도 패키지 설치 없이 Python 3으로 실행합니다.

```sh
cd /workspace/driver-manager
python3 -m http.server 8001 --bind 0.0.0.0
```

8001번 포트에 로컬 요청을 보내 HTML을 검증합니다. 클라우드의 로컬 서버 주소는 휴대폰용 공개 주소가 아닙니다.

## 휴대폰용 HTTPS 배포

정적 파일 호스팅으로 배포하면 됩니다. 배포 파일은 `index.html`, `app.js`, `style.css`, `sw.js`, `manifest.webmanifest`, `icon.svg`, `icon-192.png`, `icon-512.png`입니다. 별도 빌드나 서버 API, API 키는 필요 없습니다.

GitHub Pages용 `.github/workflows/pages.yml`을 제공합니다. 실제 배포하려면 다음 순서로 진행합니다.

1. 변경 파일을 `logan880712/driver-manager` 저장소의 main 브랜치에 올립니다.
2. 저장소 Settings → Pages → Source에서 **GitHub Actions**를 선택합니다. 저장소 공개 여부와 요금제에 따라 Pages 이용 가능 여부가 달라질 수 있습니다.
3. Actions에서 **Publish diary to GitHub Pages**를 실행하고 성공한 배포 주소를 확인합니다.
4. 휴대폰으로 실제 배포 주소를 열어 일지 저장·재접속을 확인합니다.
5. 아이폰은 Safari의 공유 → 홈 화면에 추가, 안드로이드는 Chrome 메뉴 → 앱 설치/홈 화면에 추가로 설치합니다.

현재 환경에서는 GitHub Pages API 요청이 Forbidden으로 거부되어 배포하지 않았습니다. 배포 주소와 실기기 설치는 아직 검증하지 않았습니다. 환경 설정의 Publish는 웹사이트 배포와 다릅니다.

HTTPS(또는 개발용 localhost)가 있어야 서비스 워커/오프라인 기능을 사용할 수 있습니다. 업데이트가 제공되면 기존 앱 창들을 닫고 다시 열어 새 버전을 적용합니다. 앱 업데이트 시 `sw.js`의 캐시 버전도 변경해야 합니다.

## 저장·기존 기록

데이터와 사진은 해당 브라우저의 IndexedDB에 보관합니다. 계정·서버 저장·기기 간 자동 동기화는 없습니다. 주소나 브라우저가 달라지면 별도 저장소가 사용됩니다. 브라우저 데이터 삭제·기기 분실에 대비해 전체 백업을 주기적으로 보관하세요. 백업에는 위치와 사진 등 개인 기록이 들어 있습니다. 백업 복원은 현재 기록·사진·설정을 모두 교체하며, 100MB 이하 파일을 지원합니다.

이전 버전 localStorage의 `driver-manager-v1` 기록을 첫 실행 시 IndexedDB로 이전하며 원본은 삭제하지 않습니다. 하루 일지가 있는 날짜의 기존 개별 운행은 합계에서 제외해 중복 계산을 방지합니다. 하루 일지를 삭제하면 그 날짜의 기존 개별 운행이 다시 합산됩니다.

## 피드백 계산

한국 날짜 기준으로 오늘~월말의 예정 근무일 중 아직 기록이 없는 날짜를 셉니다. 저장한 날짜는 완료한 근무일로 봅니다. 화·수 및 그 외 요일은 짧은 날 목표, 목·금은 남은 목표에서 짧은 날 목표 합계를 뺀 금액을 나눠 계산합니다. 휴무일은 추가 근무일보다 우선합니다. 추가 근무일 추정은 이번 달 실제 근무일 평균을 사용하며, 양수의 평균이 없으면 짧은 날 목표를 사용합니다. 팁은 실제 수익에 포함되지만 미래 수입 보장은 아닙니다. 계획은 수입을 보장하지 않으며 본업·수면을 고려해 조정해야 합니다.

## 검증

```sh
node --check app.js
node --check sw.js
node tests/smoke.cjs
```

마지막 명령은 Playwright와 Chromium이 설치된 개발 환경에서 사용합니다. 현재 클라우드에는 둘 다 제공됩니다. 기본 서버는 8001이며 `TEST_URL`과 `CHROMIUM_PATH`로 변경할 수 있습니다. 일지 금액/시간, 사진 보존, 수정, 유효성 검사, 백업 복원, 일정 계산, 중복 방지, 모바일 너비, 오프라인, 기존 데이터 이전을 검증합니다.
