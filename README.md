# 나의 대리일지

휴대폰에서 하루 근무일지를 쓰고 월 순수익 목표를 관리하는 설치 가능한 웹 앱(PWA)입니다.

## 기능

- 하루 일지: 근무 시작 날짜·시간, 귀가 날짜·시간, 운행 건수, 수수료 차감 후 수익, 팁, 교통비, 기타 지출, 피로도, 메모
- 운행 사진 첨부: JPEG/PNG/WebP 최대 5장, 장당 5MB. 사진을 선택하면 기기에서 OCR로 건수와 수수료 차감 후 수익을 자동 인식합니다. 상세 사진의 실수익과 목록의 총 수입을 지원합니다. 한 사진에 여러 운행이 있으면 개별 합산합니다. 고객에게 받은 현금은 재합산하지 않습니다.
- 순수익 = 수수료 차감 후 운행 수익 + 팁 − 교통비 − 기타 지출
- 월 목표 기본값 250만 원, 화·수 짧은 근무 목표 기본값 10만 원, 목·금 집중 근무 계획
- 기본 근무요일 화·수·목·금, 휴무 날짜·추가 근무 날짜 설정
- 군포역 근처 새벽 3시 전 귀가 기준, 피로도에 따른 안내
- 일지 수정·삭제, 사진을 포함한 JSON 백업·복원, 오프라인 실행, 홈 화면 설치

## 로컬 실행

별도 패키지 설치 없이 Python 3으로 실행합니다.

```sh
cd /workspace/driver-manager
python3 -m http.server 8001 --bind 0.0.0.0
```

8001번 포트에 로컬 요청을 보내 HTML을 검증합니다. 클라우드의 로컬 서버 주소는 휴대폰용 공개 주소가 아닙니다.

## 휴대폰용 HTTPS 배포

정적 파일 호스팅으로 배포하면 됩니다. 배포 파일은 `index.html`, `app.js`, `photo-parser.js`, `photo-ocr.js`, `income-charts.js`, `charts.css`, `style.css`, `sw.js`, `manifest.webmanifest`, `icon.svg`, `icon-192.png`, `icon-512.png`, `.nojekyll` 및 `vendor/` 폴더입니다. 별도 빌드나 서버 API, API 키는 필요 없습니다.

현재 휴대폰용 주소는 https://logan880712.github.io/driver-manager/ 입니다. 사용자 설정의 GitHub Pages는 `codex/driver-diary-app` 브랜치의 루트에서 배포하므로 이 브랜치에 변경을 올립니다. 원격 반영 후 Pages 배포 완료 여부는 GitHub Actions/Settings → Pages에서 확인합니다. 클라우드 환경의 GitHub Pages API/웹 요청은 제한되어 있으므로 이 환경에서는 공개 배포의 완료와 아이폰 실기기 동작을 직접 확인할 수 없습니다.

다른 저장소에서 GitHub Actions 방식으로 배포할 경우 `.github/workflows/pages.yml`을 사용하고 Settings → Pages → Source를 GitHub Actions로 선택하세요. 별도 빌드나 API 키는 필요 없습니다. 아이폰은 Safari 공유 → 홈 화면에 추가로 설치합니다.

HTTPS(또는 개발용 localhost)가 있어야 서비스 워커/오프라인 기능을 사용할 수 있습니다. 업데이트가 제공되면 기존 앱 창들을 닫고 다시 열어 새 버전을 적용합니다. 앱 업데이트 시 `sw.js`의 캐시 버전도 변경해야 합니다.

## 저장·기존 기록

데이터와 사진은 해당 브라우저의 IndexedDB에 보관합니다. 계정·서버 저장·기기 간 자동 동기화는 없습니다. 주소나 브라우저가 달라지면 별도 저장소가 사용됩니다. 브라우저 데이터 삭제·기기 분실에 대비해 전체 백업을 주기적으로 보관하세요. 백업에는 위치와 사진 등 개인 기록이 들어 있습니다. 백업 복원은 현재 기록·사진·설정을 모두 교체하며, 100MB 이하 파일을 지원합니다.

이전 버전 localStorage의 `driver-manager-v1` 기록을 첫 실행 시 IndexedDB로 이전하며 원본은 삭제하지 않습니다. 하루 일지가 있는 날짜의 기존 개별 운행은 합계에서 제외해 중복 계산을 방지합니다. 하루 일지를 삭제하면 그 날짜의 기존 개별 운행이 다시 합산됩니다.

## 피드백 계산

한국 날짜 기준으로 오늘~월말의 예정 근무일 중 아직 기록이 없는 날짜를 셉니다. 저장한 날짜는 완료한 근무일로 봅니다. 화·수 및 그 외 요일은 짧은 날 목표, 목·금은 남은 목표에서 짧은 날 목표 합계를 뺀 금액을 나눠 계산합니다. 휴무일은 추가 근무일보다 우선합니다. 추가 근무일 추정은 이번 달 실제 근무일 평균을 사용하며, 양수의 평균이 없으면 짧은 날 목표를 사용합니다. 팁은 실제 수익에 포함되지만 미래 수입 보장은 아닙니다. 계획은 수입을 보장하지 않으며 본업·수면을 고려해 조정해야 합니다.

## 검증

```sh
node --check app.js
node --check sw.js
node tests/photo-parser.cjs
node tests/smoke.cjs
node tests/photo-ocr.cjs
```

마지막 명령은 Playwright와 Chromium이 설치된 개발 환경에서 사용합니다. 현재 클라우드에는 둘 다 제공됩니다. 기본 서버는 8001이며 `TEST_URL`과 `CHROMIUM_PATH`로 변경할 수 있습니다. 일지 금액/시간, 사진 보존, 수정, 유효성 검사, 백업 복원, 일정 계산, 중복 방지, 모바일 너비, 오프라인, 기존 데이터 이전을 검증합니다.

## 사진 자동 입력

사진 선택 후 인식이 완료될 때까지 기다립니다. 입력란이 비어 있으면 건수와 운행 수익이 자동으로 채워집니다. 기존 입력이 있거나 인식 중 직접 값을 수정했다면 원래 값이 유지되고 **건수·금액 적용**으로 교체할 수 있습니다. 사진 선택을 바꾸면 해당 선택 전체를 다시 계산하며 기존 금액에 누적하지 않습니다. 같은 운행번호 또는 시간·금액이 같은 항목은 중복 후보로 제외하고, 다른 운행이라면 체크해서 포함할 수 있습니다. 이는 운행이 같다는 확정 판단이 아닙니다. 인식 결과의 금액은 직접 수정할 수 있습니다.

인식은 항상 사진과 비교해 확인해야 합니다. 일부 사진 인식이 실패하면 성공한 부분만 표시하므로 누락된 건수와 금액을 직접 반영하세요. 운행 상세·목록 사진을 대상으로 하며, 하루 전체 요약이나 다른 앱 형식은 정확하지 않을 수 있습니다. 실수익의 P는 1P=1원으로 가정합니다. 팁·교통비·기타 지출과 실제 출근·귀가 시간은 직접 입력합니다. 인식 중에는 저장 대신 완료를 기다리거나 인식 중단 후 수동 입력합니다.

Tesseract.js 7.0.0, tesseract.js-core 7.0.0 및 공식 tessdata_fast 한국어·영어 모델을 함께 배포합니다(약 7MB). 별도 API 키와 사진 업로드 서버가 필요하지 않으며 사진은 외부 서버로 전송하지 않습니다. 첫 온라인 접속 시 인식 자료를 받아 캐시하며 이후 오프라인 인식도 지원합니다. 처음 실행하거나 큰 사진은 인식에 시간이 걸릴 수 있습니다. 인식 실패 시 수동 입력을 사용할 수 있습니다. 저장된 사진을 여는 것만으로 자동 인식을 시작하지는 않습니다.

현재 Chromium에서 실제 사용자 사진 4장 → 5건 / 123,200원, 중복 제외, 수정, 기존 입력 보호, 오프라인 OCR 및 외부 요청 없음이 검증됐습니다. 실제 아이폰 Safari에서의 인식 속도·메모리 사용은 별도 확인이 필요합니다. 제3자 라이선스와 모델 출처·해시는 `vendor/ocr/`에 포함됩니다. 사용자 사진은 저장소에 포함하지 않습니다.

사진 인식 버전 1.2에서는 실패한 사진을 희소 문자 배치로 재인식하고, 계속 실패하면 수익 영역을 겹치는 구간으로 잘라 재인식합니다. 재시도 결과끼리는 더하지 않고 가장 많은 운행을 읽은 한 결과만 사용합니다. 일부 사진을 읽지 못한 경우 합계가 불완전하다고 표시합니다. 실제 첨부 사진을 원본 및 폭 590px/300px JPEG로 테스트해 모두 5건·123,200원을 확인했습니다. 실제 iPhone Safari 재검증은 필요합니다.

## 버전 2.0 사용 흐름

홈에서는 월 순수익, 목표 달성률, 남은 목표와 최근 근무를 확인합니다. 일지 작성은 사진 선택 → 수익 확인 → 근무시간·컨디션 → 저장 순서입니다. 사진을 누르면 원본을 확대해 비교할 수 있으며 사진 다시 읽기와 제거도 지원합니다. 내역의 달력에서 날짜를 누르면 그날만 조회하고 전체 날짜 보기로 돌아갈 수 있습니다. 설정의 업데이트 확인은 작성 중인 내용을 임시 보관한 뒤 새로고침합니다.

작성 중인 내용은 정식 일지와 별도로 임시 보관합니다. 입력값은 localStorage에 즉시 보관하고, 사진 포함 전체 초안은 IndexedDB에 지연 저장합니다. 임시 보관 완료 표시를 확인하세요. 초안은 누적 수익과 백업에 포함하지 않으며 정식 저장이나 새 일지 선택 시 삭제됩니다. 새로운 버전을 열어도 기존 정식 기록은 유지됩니다. 미리 저장하지 못한 사진이나 기기 저장 실패까지 복원을 보장하지는 않습니다.

사진 인식은 전체 사진을 두 가지 문자 배치로 읽어 비교합니다. 금액이 다르거나 운행 일부가 누락되면 자동 적용하지 않고 확인을 요청합니다. 실패한 사진은 수익 부분을 잘라 재인식하며, 재시도 결과끼리는 합산하지 않습니다. 사진을 잘라 읽은 결과가 더 적은 운행을 포함해도 전체 사진에서 확인한 운행 수보다 적으면 누락 상태를 유지합니다. 동일 사진은 중복 분석을 피하고, 날짜가 다른 동일 시간·금액의 운행은 별개로 취급합니다. 직접 수정한 일지 수익은 이후 분석 결과의 편집으로 자동 덮어쓰지 않습니다.

추가 검증: `TEST_URL=http://127.0.0.1:8001/ node tests/usability.cjs`로 초안의 즉시 복원·사진 복원·정식 저장 후 정리·사진 원본·업데이트 후 복원·최근 근무·달력 필터와 320/390/768px 화면을 확인합니다. iPhone 실기기에서의 최종 화면과 OCR 속도는 사용자 확인이 필요합니다.

## 근무 날짜 (버전 2.1)

한국 시간 새벽 00:00~05:59에 시작하는 새 일지는 전날을 근무 시작 날짜로 기본 설정합니다. 06:00부터 당일로 바뀝니다. 실제 출근 날짜가 다르면 직접 변경할 수 있습니다. 귀가 날짜와 상단 현재 날짜는 실제 한국 날짜를 사용합니다. 월 수익과 남은 근무 계획도 이 근무 기준일의 월을 사용하므로 월말 밤의 근무가 다음 달로 넘어가지 않습니다. 기존 저장된 일지와 작성 중인 내용이 있는 초안의 날짜는 자동 변경하지 않습니다. 날짜 외 입력이 없는 빈 초안만 새 기본 날짜를 사용합니다.

## 지난 일지와 수익 그래프 (버전 2.2)

일지 쓰기 맨 위에서 실제 근무 시작 날짜를 고릅니다. 지난달 근무도 입력할 수 있으며, 새벽 귀가 날짜는 출근·귀가 시간을 입력하면 다음 날로 계산합니다. 직접 선택한 날짜는 빈 초안 상태에서도 유지합니다. 내역에서 월 → 달력 날짜 → 선택한 날짜 일지 쓰기로도 추가할 수 있습니다. 기록한 날짜는 기존 일지 수정으로 열리고, 다른 초안을 불러오거나 기존 일지를 교체하기 전에 작성 중인 내용을 확인합니다. 지난 근무를 저장하면 해당 월의 내역을 보여줍니다.

내역의 그래프는 조회 월 전체 기록을 기준으로 순수익을 합산합니다. 월 누적 순수익 그래프의 목표는 현재 설정한 월 목표이며 과거 목표의 기록은 아닙니다. 미기록 구간은 이전 누적액을 점선으로 유지하고 미래 수입은 추정하지 않습니다. 하루 순수익 막대는 날짜순이며 음수·저장된 0원·미기록 날짜를 구분합니다. 막대를 누르면 해당 날짜 일지로 필터링합니다.

`TEST_URL=http://127.0.0.1:8007/ node tests/backdating.cjs`는 지난 날짜 초안, 지난달 야간 근무, 달력 추가, 그래프 합산·순서·음수·0원, 날짜별 수정, 초안 보호, 모바일 너비 및 오프라인 그래프를 검증합니다.
